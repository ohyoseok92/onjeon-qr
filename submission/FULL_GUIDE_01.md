## 20개 설계 기준 대응

‘적용’은 현재 코드에서 해당 방어를 확인했다는 뜻이다. 운영 조건이나 별도 기능이 남으면 함께 적었다.

| 기준 | 대응·판정 |
|---|---|
| SR1-1 DBMS 조회 및 결과 | 정적 SQLite SQL에 매개변수 바인딩, 결과 존재·소속·폐기 확인. 운영 파일 소유권 별도 필요 |
| SR1-2 XML 조회 | XML 입력·질의·파서 없음. 현재 범위에서 해당 없음 |
| SR1-3 디렉터리 서비스 | LDAP·디렉터리 인증 없음. 현재 범위에서 해당 없음 |
| SR1-4 자원·명령 입력 | 기관·키 식별자 제한, 배포자 지정 키 디렉터리, 셸 실행 없음. 파일 시스템 관리자 보호 필요 |
| SR1-5 웹 요청·출력 | 입력 길이·제어문자 제한, React 문자열 출력, JSON 오류 정제, CSP |
| SR1-6 중요 기능 요청 | 모든 발급·폐기·대시보드에 기관 토큰, 관리 API 별도 관리자 토큰. 쿠키 기반 자동 인증 없음 |
| SR1-7 HTTP | 본문 길이 실측·전체 수신5초·수신슬롯32개 상한·읽기 전 요청 제한, CRLF 사용자 헤더 생성 없음, 공식 HTTPS 링크 |
| SR1-8 메모리 접근 | Python 직접 메모리 조작 없음, 16KiB 요청·QR 크기 제한. 네이티브 의존성 패치 필요 |
| SR1-9 보안 입력 | 보안 결정은 서버 토큰·등록 공개키·발급 해시·폐기 상태에서 수행 |
| SR1-10 파일 | 업로드·임의 파일 다운로드 API 없음. QR PNG는 서버 메모리에서 생성. 의존성 설치 무결성은 공급망 보고 대상 |
| SR2-1 인증 방식 | 서버 Bearer 확인·기관 격리. 운영 관리자 MFA는 미구현 |
| SR2-2 인증 제한·추적 | 기관·관리자30회/UTC분/peer, SQLite 원자 카운터를 프로세스·재시작 간 공유, 401/403/429 보존·집계. peer 변경 공격은 운영 계층 추가 통제 대상 |
| SR2-3 비밀번호 | 사용자 비밀번호 없음. 기관 토큰256bit CSPRNG·솔트 해시·재발급. 관리자 환경 토큰 무작위 생성 필요 |
| SR2-4 접근통제 | 관리/기관/공개 API 분리, 모든 중요 요청 서버 인가. 관리자 네트워크 접근 제한 별도 필요 |
| SR2-5 키 관리 | PKCS8 암호화, 생산 암호 최소32자, 파일0600, 버전·활성·폐기 감사. KMS/HSM·백업 및 복구 승인 별도 필요 |
| SR2-6 암호 연산 | Ed25519 서명, SHA-256, 임의256bit 토큰, 신규32바이트 솔트. KCMVP 검증필 모듈 인증은 확인하지 않음 |
| SR2-7 중요정보 저장 | URL·QR 원문·시민 이력 비저장, 토큰은 해시, 발급키 암호화. Python 비밀 메모리 완전 소거는 보장하지 않음 |
| SR2-8 전송 | HTTPS 목적지·TLS 원래 호스트 검증. 배포 API HTTPS 종단의 인증서·TLS 정책은 운영 확인 대상 |
| SR3-1 예외 | 고정 오류·입력값 비반사·공통 헤더·롤백. 내부500과 감사 장애에 비밀 없는 고정 코드 로그 |
| SR4-1 세션 | 요청별 상태·기관별 인가, 브라우저 영속 토큰 저장 없음. 메모리 초기화는 서버 토큰 폐기와 다름; 장기 토큰 만료 정책 미구현 |

## 49개 구현 약점 재검토

I=입력 검증17, S=보안 기능16, T=시간·상태2, E=에러3, C=코드 오류5, P=캡슐화4, A=API2. 이 표는 49개를 각각 검토한 기록이다.

## 이번 전수 읽기에서 보완한 항목

1. **인증 실패 추적 누락**: PDF93~95·277~280·347·354쪽에 따라 기관·관리자 401/403·429를 `security_events`에 저장한다. 종류·역할·등록된 대상 기관·시간·분 단위 횟수·일/프로세스별 HMAC 출처만 기록한다. 원문 IP·자격증명·QR·URL·미등록 기관 문자열은 저장하지 않는다. 관리 성공 감사와 분리했다.
2. **감사 보존·조회**: 7일 TTL·최대10,000행을 트랜잭션으로 정리하고 최근100개만 관리자 API로 조회한다. 기관 대시보드나 공개 시민 API에서 볼 수 없다. 시작·저장·조회 및60초 주기 유휴 작업에서 정리한다. SQLite 삭제가 저장장치의 즉각적인 안전 소거를 보증하지는 않는다.
3. **감사 장애 처리**: 짧은 DB 잠금 대기 후에도 인증 거부·요청 제한은 유지한다. 고정 `SECURITY_AUDIT_WRITE_FAILED`를 60초에 최대1회 운영 로그로 남긴다. 로그 수집·경보 연결은 운영자가 검증해야 한다.
4. **일반 오류 관측**: 상세 예외 대신 고정 `REQUEST_INTERNAL_ERROR`만 내부 로그에 남겨 소스·경로·토큰·요청 원문을 노출하지 않는다.
5. **DB 파일 권한**: PDF221~224쪽에 따라 새 DB는0600, 새 전용 부모 디렉터리는0700으로 생성한다. POSIX 기존 DB도0600으로 줄인다. 기존 공유 부모 디렉터리 권한은 변경하지 않는다. Windows는 POSIX 비트를 ACL 증거로 사용하지 않는다.
6. **신규 솔트 길이**: PDF99쪽 기준에 맞춰32바이트로 확대했다. 기존16바이트솔트/무솔트256bit 토큰은 호환하고 재발급 시 신규 형식으로 전환한다. 손상된 DB 해시 형식은 거부한다.
7. **비ASCII 관리자 자격증명**: 문자열 constant-time 비교의 비ASCII 예외를 바이트 비교로 바꿔 일반403으로 처리한다. 인증 우회가 아니라 비정상500을 줄이는 수정이다.
8. **느린 본문·동시 수신**: 본문 읽기 전에 요청 제한을 적용하고 프로세스당32개 수신 슬롯·전체5초 타임아웃을 둔다. 지연 receive를 실제 ASGI로 실행해408·취소를 확인하고, 32개 동시 수신 중33번째가 본문을 읽지 않고429로 거부되는지 확인했다. 읽기 종료 시 슬롯 반환도 검증했다. 공통 보안헤더를 오류에 적용한다.
9. **CSP 폼 제출**: 로컬 ZAP 진단에서 확인한 form-action 누락을 수정해 `form-action 'self'`를 명시했다. 헤더 회귀 시험으로 정상·오류 응답을 검증했다.

## 검증과 한계

API·storage·crypto 회귀 시험에서 인증 실패401/403, 기관 제한429, 관리자 전용 감사 조회, 시민 이력 비저장, 미등록 기관/토큰/IP 비저장, 분 집계, 날짜별 출처 변경, 감사 장애 시 거부 유지, 보존일·행 상한, 기존 솔트 호환을 확인했다. POSIX 권한 시험은 Windows 환경에서 생략하며 Linux/Docker 검증은 통합 담당자가 수행한다. 최신 전체 결과는 `TEST_REPORT.md`를 따른다.

후속 조건부 재점검에서 생산 구형 토큰 거부, 공유·영속 카운터, 유휴 정리, 생산 비밀 패턴 검증, 생산CRL필수 구성을 추가했다. 실제2프로세스+재시작과61초 유휴 실행, 전체127개 시험 통과를 `SECURITY_CONDITIONS_BACKEND.md`에 기록했다. 관리자 MFA·접근망 제한·키 보관·TLS 종단·운영 로그 권한 등 다른 담당자의 검증 결과는 통합 보고서를 따른다. 기관 토큰 만료 정책, 비밀 메모리 완전 소거, 공인 진단/암호모듈 적용 여부를 코드 시험으로 확인했다고 주장하지 않는다.

가이드 일부 예시는 그대로 복사하지 않았다. PDF253쪽 시간 시드 random, 270쪽 솔트 배열 추가 예시, 300쪽 null 조건, 337쪽 DNS 비교 예시에는 의도와 맞지 않는 코드 또는 오타가 보인다. 제품에는 요구사항의 취지를 적용하고 OS CSPRNG·매개변수 SQL·표준 TLS·검증 라이브러리를 유지했다.
