# Claude Opus 코드 검토와 조치

2026-10-07에 로컬 Claude CLI를 `--model opus --effort high`로 실행해 코드 읽기 전용 검토를 두 차례 요청했습니다. 결과 JSON의 실제 모델 표기는 `claude-opus-5-5`입니다. 리뷰어에게 개인 증빙서류, 개발기획서 원본, DB, 키, 가상환경은 읽지 않도록 범위를 제한했습니다. 리뷰어는 파일을 수정하거나 시험을 실행하지 않았습니다.

1차 검토는 제출 압축 시 개인키·DB 혼입 위험, 공개 도메인 전체를 신뢰하는 정책, 토큰·키 사고 대응 수단 부족을 지적했습니다. 이에 제출 파일을 허용 목록으로만 묶는 스크립트를 만들고, 정확한 호스트 일치 정책과 토큰 재발급·기관 비활성화·키 폐기·재활성화 API를 추가했습니다.

2차 검토에서는 High 등급 문제를 찾지 못했고, 미서명 분석기의 DNS·TLS·리다이렉트 재검사 구조를 긍정적으로 평가했습니다. 다만 다음 Medium 문제를 지적해 코드를 보완했습니다.

| 지적 | 조치 |
| --- | --- |
| 느린 DNS·응답으로 분석 요청이 스레드풀을 점유 | DNS 대기 2초, HEAD 연결·응답 시간 제한, 10초 경과 시 다음 이동 중단, 동시 분석 4개 제한 |
| 한글 URL 경로에서 500 오류 | 요청 경로 퍼센트 인코딩, 예외 처리와 회귀 시험 |
| 듀얼스택 주소의 IPv6 우선 선택 | 모든 DNS 주소를 검사한 뒤 IPv4 우선 선택, 회귀 시험 |
| 속도 제한 카운터 전체 초기화·관리자 버킷 공유 | 만료 항목만 정리하고 한도 초과 시 거부, IPv6 /64 집계, 관리자·기관 요청 분리. 후속 Opus 검토에서 전역 용량 간섭을 발견해 6고정그룹별 최대1만행과 인증 실패 lane 분리로 추가 보완(최신 후속 보고서 참조) |

추가로 TLS 인증서 오류를 차단 상태로 분리하고, 비활성 기관 도메인 제외, 기관 재활성화, 깊게 중첩된 QR 입력 예외 처리, 결정적 ZIP 생성, CI 액션 SHA 고정, 직접 `pytest` 실행 경로를 보강했습니다.

이 문서는 2026-10-07 당시의 정적 검토 기록입니다. 2026-10-11에 로컬 TLS 서버를 이용한 인증서 실패·내부망 리다이렉트·헤더 시간 제한 시험을 추가했습니다. 최신 확인 범위는 TEST_REPORT.md와 SECURITY_CHECKLIST_49.md를 따릅니다. 공개 배포 보안 진단은 아직 수행하지 않았습니다. 운영망에서는 프록시의 실제 클라이언트 IP 전달, 중앙 속도 제한, 네트워크 격리 정책이 필요합니다.
