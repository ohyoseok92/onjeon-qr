## 부록의 나머지 3개 기준과 용어정리

PDF 170~172쪽의 부록은 49개 전체를 열거한다. 본문에서 제외한 메모리 버퍼 오버플로우, 해제된 자원 사용, 초기화되지 않은 변수 사용도 읽었다. 이 제품은 Python/TypeScript에서 직접 C 포인터·버퍼를 관리하지 않으므로 직접 코드 항목은 비적용이다. 네이티브 암호/파서 라이브러리의 약점까지 없다는 뜻은 아니며 버전 감사·lock·SBOM으로 별도 추적한다. 브라우저의 해제된 카메라 스트림 사용과 초기화 전 ref 접근은 별도로 시험했다.

PDF 173~175쪽은 AES·DES·HMAC·HTTPS·LDAP·SHA·umask·공개/개인키·경로순회·동적/정적 SQL·개발보안·보안약점·싱글톤·해시·allowlist·Django/Flask·파서/XML/DTD·decorator·인증서·salt의 설명이다. 이 용어들을 제품의 공개 QR/비밀 토큰 구분과 공급망/런타임 범위 판단에 적용했다. 오래된 DES/HMAC 예시나 공개키 설명을 오늘의 구현 지침 전체로 복제하지 않았다.

## 계속 확인해야 하는 항목

실제 공개 HTTPS 종단·프록시 신뢰 범위, 운영 CRL 확보·지속 갱신·역행 방지와 OCSP 정책, 관리자 신원·기관 승인·경보 담당, 휴대폰 카메라 실물 검수는 별도 확인 대상이다. 같은 SQLite의 요청 제한과 실패 이력은 구현됐으며 여러 호스트의 중앙 제한은 별도다. 전달 헤더를 신뢰하지 않으므로 같은 프록시 뒤의 정상 사용자들은 한도를 공유한다.

옛 무솔트·16bytes 솔트 토큰은 production에서 거부하며 관리자의 명시 회전으로 새 형식으로 전환한다. production 키 경로는 `<기관ID>/<키버전>.pem` 중첩 형식만 허용한다. 레거시 `<기관ID>-<키버전>.pem`은 로컬 데모에서만 호환한다. 접근권한·백업 등 구현·실증 결과와 남은 운영 조건은 최신 보안 조건 보고서를 따른다.

가이드의 Django/Flask 예제는 현재 FastAPI·React 제품에 필요한 원리를 대조하는 데 사용했다. `isalnum` 후 eval, 문자열 제거형 경로 검증, AES-CBC, SHA256 비밀번호 저장 등 예제 조각을 그대로 안전 보증으로 삼지 않았다. 제품의 목적지 도메인 검사는 정확한 호스트 일치이며 문자열 prefix 비교로 대체하지 않는다.
