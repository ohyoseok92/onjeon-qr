# 보안 설계와 확인 범위

점검일: 2026-10-11. 공식 KISA 참고가이드5종의 본문·예제·부록 **총1,307쪽을 전부 읽고** 교육자료49약점을 항목별로 대조했다. [49개 점검표](SECURITY_CHECKLIST_49.md)와 [요구사항·공급망 점검](GUIDE_SECURITY_REVIEW.md)에 코드·시험·조건을 기록했다. 읽기 기록은 [개발보안](FULL_GUIDE_01.md), [진단](FULL_GUIDE_02.md), [Python](FULL_GUIDE_03.md), [공급망·로드맵](FULL_GUIDE_04_05.md)에 있다.

## 보호 대상과 신뢰 경계

- 관리자 토큰은 환경변수로 제공한다. 기관 토큰은 임의256bit 값이며 새 토큰에는32bytes 솔트와 SHA256을 저장한다. 등록·재발급 때 한 번 반환한다. production에서는 기존16bytes 솔트·무솔트 해시를 거부한다. 개발 호환만 남기고, 전환은 관리자의 명시적 토큰 회전으로 진행한다. 사람 비밀번호를 SHA256으로 저장하도록 설계한 제품은 아니다.
- Ed25519 개인키는 DB 밖에 보관한다. `ONJEON_KEY_PASSWORD` 설정 시 암호화 PKCS8로 생성·읽으며 운영 모드는 최소32자·짧은 반복/예시 패턴 거부를 적용하며 실제 프로필은 CSPRNG48bytes로 암호를 생성한다. 평문 키를 읽는 자동 우회는 없다. 비밀 파일과 런타임 DB는 소스 ZIP에서 제외한다.
- 시민 QR·스캔 위치·IP·검증 이력은 DB에 저장하지 않는다. 요청 제한은 SQLite에 분·그룹·HMAC출처·횟수만 저장해 같은 DB 공유 워커와 재시작 사이에도 유지한다. 기관/관리자의401·403·429 보안사건은 등록기관·고정사건/코드·시각·일/프로세스별 HMAC출처·분횟수만 저장하고 원시IP·토큰·QR·URL은 제외한다. 7일/1만행 제한, 관리자 전용 조회, 저장장애 시 거부 유지와 제한된 고정 로그를 구현했다. 요청 없이 기본60초 간격의 만료 정리를 실제61초 실행해 확인했다. 프록시 로그·경보는 운영 정책이 필요하다.
- 미서명 URL 분석은 목적지에 HEAD 요청을 보낸다. 경로·쿼리의 추적 식별자가 대상 서버에 전달될 수 있다. 경고는 기관 인증이나 목적지 안전 보증이 아니다.

## 검증과 운영 조건

전체 회귀·브라우저·정적 점검·의존성 감사의 최종 수치·명령·경고·생략은 [TEST_REPORT.md](TEST_REPORT.md)를 따른다. 실제 로컬 TLS 시험은 자체서명·호스트 불일치·내부 이동·설치 주소·느린 헤더를 확인한다. 느린 body·동시32/33번째거절·사전rate는 실제 ASGI 요청으로 시험한다. 모의 정책 시험과 구분하며 QR 픽셀4방향 해독도 실제 휴대폰 성능의 근거로 대신하지 않는다. 알려진 취약점·Bandit 지적이 없다는 사실만으로 보안 전체를 보증하지 않는다.

기존 조건부7개 모두 추가 점검했다. 49개 중 **구현 확인36·비적용10·조건부3**이며 공개 TLS/백업 매체 분리(S05), 운영 CRL 갱신(S11), 발행자 신원·서명 신뢰 연결(S15)이 남는다. 로컬 통제·실행은 [SECURITY_CONDITIONS_REVIEW.md](SECURITY_CONDITIONS_REVIEW.md)에 정리했다. 이 숫자는 발견 취약점 수나 공식 인증 결과가 아니다.

- [DAST_CHECK.md](DAST_CHECK.md): 루프백 ZAP의 실제 범위·알림·수정/재검사·한계. 외부 공개 서버 전체 침투시험으로 표시하지 않는다.
- [OPERATION_SECURITY.md](OPERATION_SECURITY.md): Defender/OS·ACL·GitHub·Docker 등의 실제 조회와 미확인. Docker 엔진을 복구해 실제 build/run·HTTPS·Linux 권한·재시작 상태 유지를 확인했다. [DOCKER_RUNTIME_CHECK.md](DOCKER_RUNTIME_CHECK.md)와 JSON 증거를 따른다.
- [RECOVERY_CHECK.md](RECOVERY_CHECK.md): 임시 SQLite 온라인 backup·암호화 키 복구 및 API 확인. **오래된 백업은 이후 폐기된 QR을 되살릴 수 있다.** 복구 서버를 격리하고 최신 폐기·키/기관상태·토큰교체를 재적용한 뒤 승인해야 한다. 생산 RPO/RTO·백업 권한/보존·복구 승인을 확인한 결과는 아니다.

실제 기관 연동·도메인 소유권 승인·실물 카메라, 운영 MFA/KMS·키/토큰 수명·메모리 물리 제로화·침해 대응 담당/기한·저장소 보호/계정MFA는 추가 확인이 필요하다. JavaScript/Python의 상태/참조 제거를 물리적 메모리 영점화로 보증하지 않는다.

## 독립 Opus 검토 후 보완

Opus가 지적한 요청 제한의 그룹 간 용량 간섭, site-local IPv6 주소 누락, 백업 복구 시점 식별 부족, 운영 레거시 키 경로 충돌, CRL 만료 시 전체 시작 실패를 수정했다. 6개 고정 그룹의 카운터 용량과 인증 실패 한도를 분리하고 이전 분만 정리한다. 백업은 인증된 v2 메타데이터와 별도 HMAC 체크포인트를 대조하며 이전 세대·v1을 기본 거부한다. 운영 키는 중첩 경로만 사용한다. 정상 형식의 CRL 시간 문제는 URL 분석만 차단하고 health에 표시하며 손상된 구성은 계속 시작을 거부한다. 원래 지적과 후속 검증 범위는 `CLAUDE_OPUS_SECURITY_REVIEW_20261011.md`, `CLAUDE_OPUS_REMEDIATION_20261011.md`에 구분한다.
