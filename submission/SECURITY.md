# 보안 설계와 시험 범위

## 보호 대상과 신뢰 경계

- 기관 관리자 토큰은 환경변수에 두고, 기관 발급 토큰은 DB에 SHA-256 해시만 저장합니다. 발급 토큰은 등록·재발급 응답에 한 번 표시합니다.
- Ed25519 개인키는 DB 밖의 `.secrets`에 보관합니다. 제출 압축본에는 포함하지 않습니다.
- 시민의 QR 원문, 확인 시각, 위치, IP는 DB에 기록하지 않습니다. 속도 제한용 IP별 카운터만 서버 메모리에 1분 단위로 유지합니다.
- 미서명 URL 분석의 HEAD 요청에는 원래 경로와 쿼리가 포함됩니다. QR에 추적 식별자가 있으면 대상 서버에 분석 요청 사실이 전달될 수 있습니다.
- 기관 등록은 관리자 API 권한이 있어야 가능합니다. 실제 기관 자격·도메인 소유 확인은 운영자가 별도로 수행해야 합니다.

## 주요 위협과 방어

| 위협 | 방어 | 남는 한계 |
| --- | --- | --- |
| QR 내용 변조·위조 | 정규화된 페이로드의 Ed25519 서명, 공개키 검증, 발급 기록 해시 대조 | 개인키·관리자 토큰 유출에는 별도 운영 대응 필요 |
| 만료·폐기된 QR 재사용 | 서버의 유효기간·폐기 상태 확인 | 오프라인 검증 불가 |
| 공식 주소 사칭 | 등록된 정확한 HTTPS 호스트만 발급·검증 | 기관 도메인 소유권과 리다이렉트의 미래 상태는 별도 검증 필요 |
| 미서명 URL의 내부망 요청 | HTTP·IP 호스트 거부, DNS의 모든 주소가 공개 IP인지 검사, 확인한 IP에 TLS 연결, 이동마다 재검사 | 외부 네트워크·HEAD 응답의 한계 |
| 브라우저 자동 이동 | 서명 전에는 링크 없음. 미서명 URL은 결과에도 링크 없음 | 검증 뒤 사용자가 목적지 링크를 누르면 외부 사이트 통제 불가 |
| 요청 남용 | 요청 크기·IP별 속도 제한 | 다중 서버에는 공유 제한 저장소 필요 |
| 토큰·키 유출 | 토큰 재발급, 기관 비활성화, 키 폐기 | 운영 감사·비밀관리·배포 인프라는 별도 필요 |

## 보안 점검

자동 시험은 `tests/`에 있습니다. 의존성 취약점은 `pip-audit`, `npm audit`; Python 정적 점검은 Bandit으로 확인합니다. 결과와 실행 날짜는 `TEST_REPORT.md`를 참고합니다. 외부 공개 서버에 대한 ZAP 동적 진단이나 실제 기관 연동 시험은 수행하지 않았습니다.
